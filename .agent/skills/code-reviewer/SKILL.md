# Code Reviewer Skill

이 스킬은 프로젝트의 코드 품질을 유지하고, 기능 추가 및 수정 시 발생할 수 있는 잠재적인 문제를 사전에 방지하기 위한 코드 리뷰 지침입니다. 에이전트(사용자)가 코드 리뷰를 요청할 때 이 가이드라인을 기준으로 검토를 수행하세요.

## 핵심 리뷰 체크리스트 (Review Guidelines)

### 1. Spring Boot & Java Best Practices
- **의존성 주입**: 필드 주입(`@Autowired`) 대신 생성자 주입(`@RequiredArgsConstructor` 등)을 사용하고 있는가?
- **계층 분리**: Controller에는 비즈니스 로직이 없고, Service 계층으로 잘 위임되었는가? (MVC 패턴 준수)
- **트랜잭션 관리**: 데이터를 변경하는 Service 메서드에 `@Transactional`이 적절히 선언되어 있는가? (Read-Only 여부 구분 등)
- **예외 처리**: `try-catch`를 남용하지 않고, `@ControllerAdvice` 또는 전역 예외 처리기(Global Exception Handler)를 통해 일관성 있게 예외를 던지고 있는가?

### 2. 성능 및 데이터베이스 (Performance & DB)
- **N+1 문제**: JPA 연관 관계 조회 시 N+1 문제가 발생할 여지가 있는가? (`Fetch Join`, `EntityGraph` 고려 여부)
- **불필요한 쿼리**: 반복문 내에서 DB I/O가 발생하지 않는지 확인.
- **캐싱 및 리소스**: 자주 조회되는 무거운 데이터의 경우 캐싱이나 효율적인 검색/페이징 쿼리가 적용되었는가?

### 3. 코드 가독성 및 유지보수 (Clean Code)
- **네이밍 컨벤션**: 클래스, 메서드, 변수 이름이 직관적이고 의도를 명확하게 전달하는가? (자바 카멜 케이스 준수)
- **단일 책임 원칙 (SRP)**: 하나의 클래스/메서드가 너무 많은 책임을 지고 있지 않은가? (메서드는 가급적 작게 유지)
- **매직 넘버/스트링**: 코드 내에 하드코딩된 문자열이나 숫자가 상수(`static final`) 리스트 혹은 프로퍼티로 잘 분리되어 있는가?

### 4. 테스트 및 안전성 (Testing & Security)
- **테스트 커버리지**: 비즈니스 로직 변경 시 관련된 단위 테스트(Unit Test)가 함께 작성되었거나 수정되었는가?
- **입력 검증**: Controller의 DTO/Request 객체에 적절한 Validation(`@NotBlank`, `@Size` 등)이 포함되어 있는가?
- **보안**: 권한 확인(`@PreAuthorize`, `SecurityContextHolder` 등)이 필요한 엔드포인트가 무방비로 열려 있지 않은가?

## 사용 방법 (How to use)

유저가 코드 리뷰를 요청하면, 다음 포맷에 맞추어 피드백을 제공하세요:

1. **[총평]**: 변경 사항(또는 해당 코드)에 대한 전반적인 인상과 요약.
2. **[👍 잘된 점]**: 칭찬할 만한 코드 작성 사례.
3. **[🛑 개선 필요 (Critical)]**: 버그 발생 위험이 있거나 성능 저하를 일으킬 수 있는 치명적 문제. (코드 수정 제안 필수)
4. **[💡 권장 사항 (Optional)]**: 더 나은 디자인 혹은 가독성을 위한 리팩토링 제안.
